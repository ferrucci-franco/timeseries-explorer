# Time Series Explorer v0.1.1

Large files: faster where it counts, and honest about what it cannot do. Plus a Parquet converter you can reach without opening anything.

## Downloads

- **Windows 10/11 x64:** installer and portable EXE.
- **macOS Intel:** DMG installer and ZIP package.
- **macOS Apple silicon:** DMG installer and ZIP package.
- **Linux x86_64:** DEB installer and AppImage package.
- **SHA256SUMS files:** checksums for verifying the downloaded packages.

The executables are currently unsigned. Windows SmartScreen may therefore show an **Unknown publisher** warning. Verify that the file was downloaded from the official Time Series Explorer download button and compare its SHA-256 checksum before running it.

## Faster

- **Data Tools off the main thread.** Outlier removal, resampling and the rest run as pure kernels in a worker, so the window keeps responding while they work. The maths is unchanged — the rewrites are bit-exact against the previous implementation.
- **Every format parses off the main thread**, not only CSV. A large MAT, pickle or netCDF no longer freezes the tab while it is read.
- **Zoom decimates in place.** Panning and zooming a large file no longer copies the visible slice before thinning it.
- **Derived formulas are compiled** instead of interpreted per sample. `diff(x)` and friends are 1.5–3.5× faster on large series.
- **A workbook is decoded once, in a worker.** Opening a spreadsheet used to read it on the main thread purely to list its sheets — about a minute of a frozen tab for a 126 MB file, with Firefox offering to stop the page.

## Large files

- **Oversized files are a warning, not a refusal.** The limit per format now asks whether to open the file anyway instead of declining for you, and the answer lasts only for that load — change your mind and it asks again.
- **Failures are explained in the app's own words.** Out of memory, a killed reader, a string too long for the browser: each says what happened and what to do, instead of forwarding a raw browser message.
- **A crashed renderer is reported** rather than leaving a blank window.

## Convert to Parquet

- **From the menu, without opening anything.** *Convert a file to Parquet…* takes a text file or a spreadsheet, lets you check the parsing first, asks where to save, and stops there.
- **Any delimited text file**, not just `.csv`, and **spreadsheets in both versions** — the browser converts them too, not only the Full Desktop build.
- **The parsing is always shown before converting.** A conversion of a misread file is worse than no conversion, because the result looks authoritative.
- **The file it writes is usable.** Columns keep their real types instead of arriving as text, the columns you unticked are actually left out, dates stay dates, and the time column keeps the name it had.
- **Cancellable, and cancelling means something.** The conversion stops within a fraction of a second, and nothing is written or opened.
- **Where it goes is asked before the work starts**, so the browser's save dialog can actually open. Where a browser offers none — Firefox, Safari — it says so up front instead of quietly downloading the file and calling it saved.

## Fixes

- A trace dropped onto a zoomed panel now fills in the viewport, instead of staying at overview resolution while every trace beside it shows detail.
- The query engine is shut down when the last file is closed, returning memory that a WebAssembly heap can otherwise never give back.
- A spreadsheet sheet too large to build is reported as out of memory, not as "sheet not found" or "no sheets with data".
- Escape cancels a load from the first second, including while a workbook is being prepared.
- The version row is dated by its commit rather than by the clock of whatever machine compiled it.
- The Full Desktop download no longer calls the build a beta.
- *Release details* sits beside the version in the download dialog, instead of at the foot beside Close.

## Help

The *Large files and memory use* section was rewritten for a reader who is not a programmer: what a limit is before what the limits are, which of them switch a file to memory-saving mode and which only warn, what changes between the browser and the Full Desktop version, and what the app can and cannot do about a file that does not fit.

## Desktop capabilities

- Fully local, offline application and bundled processing libraries.
- External documentation links open in the operating system's default browser.
- No classic Electron menu or secondary Electron browser windows.
