# Real-world CSV corpus

Delimited-text files written by real instruments, data loggers, PLC/HMI/SCADA systems and
scientific software, collected as a stress corpus for the CSV/text parser benchmark.

Every file is a byte-exact copy of a file published in a public repository (GitHub). Nothing
was generated, re-encoded, trimmed or re-saved by us. A few files had been trimmed or edited
upstream by their authors, and the `quirks` field in the manifest says so.

- **108 files**, 13.2 MB, largest 1.4 MB.
- **Header / metadata languages:** en (63), de (11), es (6), fr (5), it (4), nl (4), ru (3), ja (3), sl (1), cs (1), sr (1), vi (1), pt (1), ko (1), sv (1), zh (1).
- **Encodings:** ascii (65), utf-8 (33), latin-1 (2), shift_jis (cp932) (2), latin-1/cp1252 (2), cp866 (1), cp1251 (1), utf-8 (with U+FFFD in unit line) (1), utf-16le (1); 22 files start with a BOM.
- **Line endings:** LF (72), CRLF (35), CRCRLF (1).
- **Decimal comma:** 19 files.

## Layout

```
manifest.jsonl          one JSON object per file (provenance, encoding, dialect, quirks, sha256)
verify.mjs              checks sha256 of every file; --fetch re-downloads missing/changed ones
lab-instruments/        Lab instruments (scopes, analyzers, DAQ, loggers)
industrial-energy/      Industrial automation & energy (PLC, HMI, SCADA, relays, meters, inverters)
field-environment/      Field dataloggers & met/hydro services
mech-chem-bio/          Mechanics, vehicles, chemistry, batteries, biomedical
```

`.gitattributes` marks the four data folders `-text`, so git stores and checks out the bytes
as they are: CRLF, CR CR LF, UTF-16 and BOMs are part of what is being tested.

## Manifest fields

`path`, `category`, `sha256`, `source_url` (raw URL pinned to a commit), `repo`, `repo_license`
(`none` = the source repo declares no licence), `domain`, `device_or_software`, `language`,
`encoding`, `bom`, `line_endings`, `delimiter`, `decimal_separator`, `header_lines` (approximate
preamble length before the data), `quirks`, `size_bytes`, `rows_approx`, `realness_evidence`.

The dialect fields describe the file as a person reading it would; they are a starting point
for the benchmark's expected results, not a verified ground truth.

## Licences

59 files come from repositories with an explicit licence (MIT, GPL, Apache, CC, ...).
**49 come from repositories that declare no licence**, and one (`fronius-solarweb_export_de_units-row.csv`)
is CC-BY-NC-4.0. Before redistributing this folder outside the project, check `repo_license` per file;
`verify.mjs --fetch` can rebuild any file that was left out from its pinned URL.

## Known gaps

GitHub code search does not index files that are not UTF-8, so GBK/GB2312 (Chinese instruments and
battery cyclers), more Shift-JIS (Hioki, Graphtec in Japanese mode) and more UTF-16 exports
(Agilent ChemStation reports) were hard to find. Nothing usable turned up for Rockwell FactoryTalk,
Ignition, CODESYS trace, PMU/synchrophasor exports or raw wind-turbine SCADA. Government data portals
(DWD, USGS, INMET, Zenodo, ...) were not reachable from the collection environment, so their files
here are copies that someone committed to GitHub.
